Agent Skills

You’ve been using skills all day

When you asked Posit Assistant for help today, it loaded .agents/skills/help/SKILL.md.

A skill is a folder with a SKILL.md file: a description of when to use it, plus instructions for how to do the job.

Open .agents/skills/help/SKILL.md live and scroll through it. Attendees have been on the receiving end of this skill all morning.

The same format works across agents: Posit Assistant, Claude Code, and many others follow the Agent Skills spec.

Skills are plain markdown, checked into your project — no packaging, no build step.

Anatomy of a skill

skills/
└── renewal-letters/
    ├── SKILL.md      # Required: metadata + instructions
    ├── scripts/      # Optional: executable code
    ├── references/   # Optional: documentation
    └── assets/       # Optional: templates, data files

SKILL.md

---
name: renewal-letters
description: Draft a renewal letter for a lapsed Last Blockbuster member.
---

# Renewal letters

Offer Basic members a free-rental code.
Offer Family members a family-night bundle.
Offer Founders members a commemorative card.

Agent Skills specification

Two required frontmatter fields:

  • name: lowercase, hyphens, max 64 characters, must match the folder name.
  • description: max 1024 characters, and it must say what the skill does AND when to use it.

The description is the only thing the agent sees at startup, so it decides whether your skill ever gets used.

The body is free markdown: steps, rules, gotchas, a template.

Progressive disclosure

  1. Discovery — the agent loads only each skill’s name and description (~100 tokens each)

  2. Activation — when a task matches, the agent reads the full SKILL.md

  3. Execution — instructions run; extra files load only when the skill asks for them

This is why skills scale: you can keep 100 skills on hand for the cost of their descriptions.

The full instructions load only when a task calls for them.

Same idea you’ll implement by hand in the exercise: the system prompt lists the skill, a tool loads the body.

Why not just use the system prompt?

  • The system prompt is always in context — every token, every request

  • Skills load on demand — only when a task matches

  • So skills let you give an agent deep expertise without paying for it up front

You wrote a system prompt for the Blockbuster agent. That works for one small set of rules.

Now imagine 50 jobs: renewal letters, store opening procedures, staff notes, rental policies, and social media voice.

Stuffed into the system prompt, they crowd out the conversation and cost tokens on every request.

As skills, they cost about 100 tokens each until the moment one is needed.

Writing a skill that works

  • Add what the agent lacks; omit what it knows — no “write clear descriptions”

  • Description says what and when — it’s the trigger

  • Concrete beats generic — a template, a rule, a gotcha

  • Keep it short — under 500 lines; push detail to references/

Best practices for skill creators

The test for every line: would the agent get this wrong without it?

If the agent already writes clean markdown, don’t tell it to write clean markdown.

Give a default, not a menu: one way to do it, with an escape hatch.

Gotchas are the highest-value content: the environment-specific facts that defy reasonable assumptions.

  1. Your Blockbuster agent gets a skill: renewal-letters holds the letter-writing instructions.

  2. List the skill in the system prompt, and give the agent a tool to read it.

  3. Draft letters for the top three lapsed members. Watch the agent read the skill before it starts drafting.

The read_skill tool is like the read_file tool, pointed at the skills folder.

The system prompt listing is the manual version of what real harnesses generate automatically at startup.

The trace should show read_skill firing when the agent starts the letter task.

Your Turn 25_skills-2

  1. The skill has been swapped for a first draft with common problems.

  2. Use the diagnostic questions to fix SKILL.md, then re-run the letter task.

  3. Compare: same agent, same tools, different skill, different letters and token spend.

The planted problems: the description is background about the manager’s notes, while the actual trigger sits in the body. The body also repeats policies, generic advice, and conflicting process instructions.

Four questions lead attendees from the misplaced trigger to the repeated facts and conflicting process. They move and delete text; they do not need to invent new instructions.

The good skill says when to draft a renewal letter and keeps only the voice, letter structure, tier incentives, filename rule, and promises caveat.

Skills, recap

  • A skill is a folder with SKILL.md: metadata plus instructions

  • Progressive disclosure: descriptions at startup, body on demand

  • Write what the agent doesn’t know — and say when to use it

  • Same format in Posit Assistant, Claude Code, and any spec-following agent
